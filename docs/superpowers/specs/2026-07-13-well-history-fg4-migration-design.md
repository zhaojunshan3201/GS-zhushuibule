# 单井井史 FG4 功能迁移设计

## 目标

将 `C:\Users\31541\Desktop\7.6\FG4\gszhushuiSQL` 中“单井井史”页面的全部前后端能力迁移至当前系统，同时不覆盖当前系统中与井史无关的既有改动，并保持已有井史数据可读取。

## 范围

迁移以下 FG4 专有能力：

- PPTX 原件的上传、解析、页面内编辑、下载和版本管理；
- 富文本井史的编辑、图片引用处理和版本管理；
- 对应的井史目录详情字段、API、上传文件存储和删除级联；
- Prisma 模型与两份数据库迁移；
- 支撑功能的共享工具、React 组件、依赖和自动化测试。

现有的 PDF 上传、批量导入、目录检索、PDF 内容/叠加编辑及当前系统其他页面不在重构范围内，仅在需要时与新增能力衔接。

## 实现策略

采用定向迁移，而不整体替换 `src/App.tsx` 或 `server.ts`。

1. 对比 FG4 与当前系统的井史相关代码，只合并页面状态、类型、处理函数和 JSX 区块。
2. 迁移 `PptxWellHistoryEditor`、`WellHistoryRichTextEditor`、PPTX 解析写入工具和富文本清洗工具。
3. 合并服务端井史专用接口、PPTX/富文本文件及版本持久化逻辑；保持当前非井史 API 不变。
4. 将 FG4 的 PPTX 与富文本 Prisma 模型及迁移加入当前系统，使新表以独立迁移创建，不修改或重建已有井史表。
5. 补齐 FG4 为这些模块提供的 npm 依赖；不更改与井史无关的依赖。

## 数据与兼容性

- 现有 `WellHistoryArchive` 记录保持有效；新增关联字段允许为空，因此旧记录可继续仅使用 PDF 功能。
- 新建 PPTX、富文本及版本记录按井号和档案 ID 关联，并使用级联删除规则清理附属记录。
- 井号规范化、既有 PDF 文件目录和原有检索接口沿用当前系统实现，避免改变历史 URL 或数据格式。

## 验证

1. 先迁移 PPTX 与富文本的单元测试，确认在目标系统中初始失败或暴露缺失模块。
2. 完成最小实现后运行全部井史相关测试，覆盖文件名解析、PPTX 解析/写入与富文本清洗。
3. 执行 Prisma 生成与迁移校验、TypeScript 类型检查和生产构建。
4. 逐项手工核对：目录查询、PDF 功能、PPTX 编辑/下载/版本、富文本编辑/保存/版本、删除级联以及旧档案打开。

## 非目标

- 不整体同步 FG4 的其他页面或服务端改动；
- 不迁移 FG4 工作树中的试验性或与“单井井史”无关的代码；
- 不对当前系统做无关格式化、重构或数据清理。
