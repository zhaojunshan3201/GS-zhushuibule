# 单井井史重复覆盖与侧边栏调整设计

## 目标

1. 同一次批量上传中出现重复井号时，按文件选择顺序由最后一个文件覆盖前面的文件。
2. 将井史正文上方的井信息、筛选查询、保存和下载功能迁移到左侧栏。

## 重复井号处理

- 服务端继续以规范化井号分组。
- 每组仅处理选择顺序中的最后一个文件，避免为被覆盖文件执行 PowerPoint COM。
- 同组内更早的文件在返回结果中标记为 `superseded`，提示“已被同批次后续文件覆盖”。
- `superseded` 属于成功跳过，不计入 `successCount` 或 `failureCount`；响应新增 `supersededCount`。
- 实际处理的最后一个文件仍使用现有 upsert 逻辑覆盖数据库中的当前 PPTX 和富文本，并保留版本记录。
- 前端完成提示展示：总文件数、成功数、覆盖跳过数、失败数。

## 侧边栏布局

左侧栏从上到下排列：

1. 当前井信息：井号、单位、区块、更新时间；未选择井时显示占位信息。
2. 查询与操作：单位选择、区块选择、井号输入、查询按钮、保存编辑结果、下载 PDF。
3. 批量导入进度。
4. 井史目录。

正文区域删除原顶部导航/操作栏，只保留加载态、井史富文本编辑器、PDF 编辑器或空状态。

## 状态与行为

- 查询、保存、下载继续调用现有处理函数，不改变业务行为。
- 保存和下载按钮沿用当前禁用条件。
- 当前井切换、未保存内容确认和导入后自动打开第一条成功记录保持不变。
- 左侧栏在宽屏保持 320px，窄屏继续堆叠在正文上方。

## 测试

- 服务端单元测试覆盖同批次重复井号仅选择最后一个，并正确返回被覆盖文件。
- 前端源码契约测试确认查询、保存和下载控件位于左侧栏，正文顶部不再重复渲染。
- 运行 `npm test`、`npm run lint`、`npm run build`。
