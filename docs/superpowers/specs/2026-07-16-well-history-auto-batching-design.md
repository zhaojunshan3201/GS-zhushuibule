# 单井井史 PPT 自动分批导入设计

## 目标

支持一次选择超过服务端单批限制的 PPT/PPTX 文件，前端自动拆分并顺序导入，同时保留重复井号最后文件覆盖规则。

## 分批规则

- 单批最多 20 个文件。
- 单批文件内容总量最多 48MB，为 multipart 边界和字段预留空间，确保请求 Content-Length 不超过服务端 50MB。
- 按文件选择顺序使用贪心方式分批。
- 单个文件超过 50MB 时阻止本次导入，并在弹窗中列出超限文件。

## 超限确认

- 当文件总数超过 20 个或内容总量超过 48MB 时，在上传前弹出确认框。
- 提示选择文件数、预计批次数和自动分批说明。
- 用户确认后开始；取消后清空文件输入，不发送请求。

## 重复井号

- 在分批前使用共享井号文件名解析和去重逻辑处理全部选择文件。
- 相同规范化井号仅保留选择顺序中的最后一个文件。
- 前序重复文件作为 `superseded` 汇总，不发送到任何批次。
- 由此前序重复文件不会跨批重复执行 COM，最终结果仍是最后文件覆盖。

## 执行与进度

- 批次串行发送到现有 `/api/uploads/well-history-ppt-batch`。
- 状态显示“正在导入第 X/N 批”。
- 上传进度按当前批次在总批次数中的比例折算，完成后为 100%。
- 单批请求失败时，该批文件记为失败，并继续后续批次。
- 聚合所有响应的 `successCount`、`supersededCount`、`failureCount` 和 `items`。
- 全部结束后刷新目录、打开第一条成功记录，并显示一次汇总弹窗。

## 测试

- 共享纯函数测试覆盖按数量/体积分批、选择顺序、48MB 边界和单个超限文件。
- 前端源码契约测试覆盖超限确认、批次状态和汇总字段。
- 运行 `npm test`、`npm run lint`、`npm run build`。
