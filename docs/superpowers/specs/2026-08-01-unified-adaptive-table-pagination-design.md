# 统一表格高度自适应分页设计

## 背景

“智能测调井史”已经支持根据屏幕可用高度动态调整每页行数，其余业务表格仍固定显示 10、15 或 30 行。固定分页会在大屏产生明显留白，也会让不同页面的分页体验不一致。

本次将同一套高度自适应分页能力推广到十个业务页面，保持服务端数据分页、原有筛选与增删操作不变。

## 目标

- 所有目标页面根据屏幕可用高度动态显示 10～25 行。
- 约 900px 高的视口显示约 15 行，约 1080px 高的视口显示约 19 行。
- 窗口缩放后尽量让旧页首条记录仍位于新页可见范围。
- 宽表继续在表格容器内部横向滚动，不产生页面级横向溢出。
- 数据增加后继续使用现有分页机制，不一次性渲染全部数据。
- 所有页面共用一套 Hook，避免重复维护缩放和页码映射逻辑。

## 页面范围

1. 智能测调井史
2. 同心测调井史
3. 单井注入评价
4. 单井密封评价
5. 含水化验
6. 注水工艺
7. 水井洗井
8. 异常水井
9. 动态调配
10. 指示曲线

## 非目标

- 不修改数据库结构。
- 不修改现有 API 路由或响应结构。
- 不改变筛选字段、表头、业务数据计算或表格配色。
- 不把主表改为无限滚动或虚拟列表。
- 不改变含水趋势曲线、指示曲线图表及其大批量数据查询口径。

## 统一架构

### 共享纯函数

继续使用现有函数：

- `calculateAdaptiveTablePageSize`：根据视口高度、表格顶部、底部预留空间和行高计算 10～25 行。
- `mapPageForPageSizeChange`：在 pageSize 改变时，根据旧页首条记录索引计算新页码。

### 共享 Hook

新增 `useAdaptiveTablePagination`，统一管理：

- `currentPage`
- `pageSize`
- 表格页面容器 `ref`
- 当前页和当前 pageSize 的同步引用
- `resize` 监听器
- `requestAnimationFrame` 合并
- pageSize 改变后的页码映射

Hook 返回当前页、更新当前页的方法、当前 pageSize 和表格容器 ref。页面不再自行声明固定分页常量，也不再复制窗口监听代码。

默认规则：

- `minRows = 10`
- `maxRows = 25`
- `reservedHeight = 184`
- `rowHeight = 41`
- 无浏览器环境或无有效测量值时安全回退到最少 10 行

表格容器使用实际 `getBoundingClientRect().top`；无法测量时使用 80px 回退值。

## 数据流

### 服务端分页页面

以下页面的主表继续服务端分页：

- 智能测调井史
- 同心测调井史
- 单井注入评价
- 单井密封评价
- 含水化验
- 注水工艺
- 水井洗井
- 异常水井
- 指示曲线

行为要求：

1. 主表请求始终携带共享 Hook 返回的 `pageSize`。
2. pageSize 改变时，使用映射后的当前页重新请求。
3. 筛选条件改变时回到第 1 页，并使用当前 pageSize。
4. 新增、删除后的刷新继续使用当前 pageSize。
5. 服务端返回的实际页码用于同步当前页。
6. 每个页面的主表加载必须使用递增请求 ID 或等价方式，只有最新请求能提交数据、页码和错误状态。

特殊查询保持原逻辑：

- 指示曲线的图表数据和选项数据仍按原有较大数量查询，只有主表请求使用自适应 pageSize。
- 含水化验趋势曲线的历史数据仍按原有数量查询，只有主表请求使用自适应 pageSize。

### 前端分页页面

“动态调配”继续一次加载当前查询结果，在浏览器中分页：

1. pageSize 改变时不重复请求服务器。
2. 使用新的 pageSize 重新计算 `visibleRows` 的当前页切片。
3. 使用同一个首记录索引映射规则更新当前页。

## 页面布局

- 每个目标页面使用一个可测量的外层容器包住主表区域。
- 主表仍随数据行数自然增长，不使用固定像素高度裁切数据。
- 小屏低于可容纳 10 行时，页面允许纵向滚动。
- 宽表保留现有 `min-width` 和内部 `overflow-x` 容器。
- 页面级 `body` 不应因表格宽度产生横向滚动。
- 数据少于 pageSize 时只显示真实数据，不生成虚假业务行。
- 指示曲线现有视觉补行继续根据动态 pageSize 计算。

## 错误和竞态处理

- 请求开始时沿用页面现有的错误清理和加载状态。
- 旧成功响应不得覆盖新请求的记录、总数或当前页。
- 旧失败响应不得覆盖新请求的成功状态。
- 页面卸载时移除 `resize` 监听并取消尚未执行的动画帧。
- API 加载失败时继续显示页面原有错误提示，不改变错误文案。

## 测试策略

### 单元测试

- 900px 视口约 15 行。
- 1080px 视口约 19 行。
- 小视口夹到 10 行。
- 大视口夹到 25 行。
- 非法尺寸安全回退。
- pageSize 增大或减小时正确映射旧页首记录。
- Hook 正确注册和清理 resize/animation frame。

### 页面集成测试

- 十个页面全部使用共享 Hook。
- 目标页面不再使用固定主表 pageSize 常量。
- 九个服务端分页主表使用动态 pageSize 请求。
- 动态调配使用动态 pageSize 进行前端切片。
- 指示曲线补行数量跟随动态 pageSize。
- 主表加载具有仅最新请求提交状态的保护。

### 浏览器验收

每个页面至少验证：

- 1600×900 时约显示 15 行。
- 1920×1080 时约显示 19 行。
- 1280×900 时页面无整体横向溢出，宽表在内部横向滚动。
- 在第 2 页改变视口高度后，旧页首条记录仍在新页可见范围。
- 查询、新增、删除和分页未回归。
- 页面无新增控制台错误。

### 项目验证

- `npm test`
- `npm run lint`
- `npm run build`
- `git diff --check`

## 成功标准

- 十个页面全部统一使用 10～25 行高度自适应分页。
- 大屏不再因固定 10 或 15 行产生明显无效留白。
- 含水化验从固定 30 行改为统一的 10～25 行规则。
- 数据增多后仍通过分页完整访问。
- 缩放、筛选和翻页交错时不会出现旧数据覆盖新状态。
- 现有未提交工作和无关页面不受影响。
