# 管理员自定义首页储量看板颜色设计

## 目标

允许具有现有系统设置访问权限的管理员，在“系统设置”中通过可视化取色器自定义首页储量分析看板的五种语义颜色。配置全局持久化；用户刷新或重新进入首页时读取新颜色，不要求已打开页面实时更新。

## 自定义范围与默认色

| 指标 | 默认色名称 | 默认色值 |
| --- | --- | --- |
| 上年度产油 | 鲜红 | `#EF4444` |
| 动用储量 | 蓝 | `#2563EB` |
| 可采储量 | 紫红 | `#C026D3` |
| 标定采收率 | 蓝灰 | `#486581` |
| 总体贡献 | 暗红 | `#7F1D1D` |

取色器支持完整色谱。管理员可以选择黄色、绿色或其他任意有效颜色，不限制为默认色系，也不强制限制亮度或对比度。

## 配置结构与数据流

- 使用现有 `SystemConfig` 表和 `/api/config` 接口，不新增数据库表或迁移。
- 五项颜色作为一个 JSON 对象，以 `homeReserveChartColors` 配置键保存。一次请求原子更新整套色板，避免多项配置部分成功。
- 新增独立的颜色配置模块，集中维护字段类型、默认色、`#RRGGBB` 校验、JSON 解析和逐项回退逻辑。
- 系统设置页加载 `/api/config` 后解析颜色配置，并将结果作为五个取色器的初始值。
- 首页进入时并行请求储量数据与 `/api/config`，解析色板后传入 `HomeReserveAnalysisDashboard`。
- 看板继续让同一语义颜色服务于对应指标卡、柱形、折线、图例和总体贡献进度条。
- 不增加实时广播或浏览器存储。管理员保存后，已经打开首页的用户保持原色；刷新或重新进入首页后应用新配置。

## 管理员界面与交互

- 在“系统设置”中新增独立的“首页储量看板颜色”区域，不混入现有基础文字配置输入列表。
- 按指标提供五个 `type="color"` 可视化取色器，不提供可编辑的十六进制输入框。
- “恢复默认色”只把当前表单中的五个取色器恢复为上述默认值，不立即写入服务器。
- 管理员必须点击“保存颜色”才提交整套配置。
- 保存成功或失败复用系统设置页现有消息提示；保存失败时保留当前选择，允许直接重试。
- 五个取色器在窄屏自动换行，不改变首页看板布局。
- 权限沿用现有系统设置访问规则，不新增独立的角色或单位判断。

## 校验与错误处理

- 保存值统一规范为大写或小写均等价的六位 `#RRGGBB` 格式。
- JSON 配置缺失时使用整套默认色。
- JSON 可解析但某个字段缺失或无效时，仅该字段回退默认值，其余有效自定义颜色继续使用。
- `/api/config` 读取失败时，首页储量数据仍可正常加载，看板使用整套默认色。
- 颜色保存失败时显示现有错误提示，不覆盖管理员当前表单选择。

## 组件边界

- 共享颜色配置模块只负责类型、默认值、序列化、解析与校验，不负责网络请求或 React 状态。
- `SystemSettingsPage` 负责取色器状态、恢复默认和保存请求。
- `HomePage` 负责并行加载储量数据与全局配置，并把解析后的色板传给看板。
- `HomeReserveAnalysisDashboard` 只消费传入色板并渲染，不直接请求配置接口。

## 测试与验收

1. 默认配置精确对应鲜红、蓝、紫红、蓝灰和暗红五个色值。
2. 解析器接受黄色、绿色等任意合法 `#RRGGBB` 值。
3. 缺失、损坏 JSON 和单项非法颜色按设计回退，且不丢弃其他合法项。
4. 系统设置页包含五个可视化取色器、“恢复默认色”和“保存颜色”；不包含可编辑的十六进制文本框。
5. 恢复默认只修改本地表单，只有保存操作才写入 `homeReserveChartColors`。
6. 首页刷新或重新进入时加载全局颜色配置；配置失败时储量看板仍使用默认色显示。
7. 指标卡、组合图、排名图和总体贡献进度条使用对应的自定义语义颜色。
8. 系统设置权限、首页布局、储量数据结构和其他页面行为保持不变。
9. 相关聚焦测试、TypeScript 检查和全量测试通过。

## 不在本次范围

- 不提供实时跨页面或跨用户颜色同步。
- 不新增色彩对比度警告、调色板模板、历史版本或导入导出。
- 不允许普通用户在个人浏览器中覆盖管理员配置。
- 不修改全局主题、其他图表或表格颜色。
