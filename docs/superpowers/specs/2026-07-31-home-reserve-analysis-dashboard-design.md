# 首页储量分析看板设计

## 目标

在现有“储量概览列表”上方增加 B 方案的分析看板，使管理人员先看到总体储量、采收能力、单位差异和区块贡献，再通过下方原表核对精确数据。

## 页面结构

页面从上到下分为三层：

1. **标题与状态**：显示“储量分析看板”、数据口径提示和当前加载状态。
2. **分析看板**：
   - 四张核心指标卡：动用储量、可采储量、标定采收率、上年度产油。
   - 区块多指标组合图：使用柱形展示动用储量和可采储量，使用折线展示上年度产油；双轴明确区分储量与产油单位。
   - 区块贡献排名：按动用储量从高到低排列水平条形图，显示区块名称、数值及占总体比例。
   - 采一 / 采二对比：并列展示两单位的动用储量、可采储量和采收率，突出结构差异。
3. **原始明细表**：完整保留当前列、行、分组、小计与合计，放在分析看板下方。

## 图表表达规则

- 动用储量使用深青色，可采储量使用琥珀色，上年度产油使用蓝灰色折线，保持跨图表语义一致。
- 图表只使用 `rowType === "block"` 的区块数据，避免小计和合计重复计入。
- 指标卡和单位对比使用接口返回的小计/合计行；若缺少小计或合计，则从区块行即时汇总。
- 所有图表提供 Tooltip、图例、坐标单位与精确数值；颜色之外同时依赖形状、标签和图例传达含义。
- 桌面端采用两列分析布局；窄屏自动变为单列，原表保持横向滚动。

## 组件与数据流

- `HomePage` 继续只请求一次 `/api/home-reserve-overview`。
- 在页面内部从 `rows` 派生 `blockRows`、`subtotalRows`、`totalRow` 和排名数据，不新增后端接口或持久化字段。
- 使用项目已有的 Recharts 实现组合图和水平条形图；指标卡和单位对比使用普通 React/Tailwind 结构。
- 图表与表格共享相同的格式化函数，保证小数位和百分号一致。

## 状态与错误处理

- 加载中：看板显示轻量骨架/加载提示，表格维持现有加载行。
- 接口失败且没有数据：显示现有错误信息，不渲染空图表。
- 已有数据后出现错误：保留已加载图表和表格，并显示非阻断错误提示。
- 零值或缺失值按 `0` 参与图表计算，Tooltip 明确显示 `0`，不制造虚假趋势。

## 验收标准

1. B 分析看板位于现有储量表格上方，原表字段、顺序、小计和合计不变。
2. 四张指标卡与表格合计值完全一致。
3. 组合图只含六个区块，能同时比较动用储量、可采储量和上年度产油。
4. 区块贡献排名按动用储量降序，数值和占比准确。
5. 采一 / 采二对比与两条小计行一致。
6. 1280px 以上为清晰双列布局；窄屏不重叠、不裁切，表格可横向滚动。
7. 项目现有测试通过，并增加数据派生/排序测试覆盖图表输入。

## 不在本次范围

- 不修改后端数据结构、管理录入流程或现有表格字段。
- 不增加时间筛选、钻取页面、导出、动画大屏或新的权限逻辑。
